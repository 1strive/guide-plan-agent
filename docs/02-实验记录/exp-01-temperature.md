# 实验 01：temperature 对输出的影响

> 关联：`docs/开发规划.md` Task 1.1（输出物之一）；`docs/01-面试八股文/09-Prompt工程.md` §2.4 迭代优化、§2.1 清晰性。
>
> 目的：在固定 prompt 与模型下，对比 `temperature` 取 `0.0 / 0.4 / 0.9` 时 LLM 输出的差异，建立"参数会动什么"的直觉，作为后续 Task 2.3 Prompt 评测框架的基线。

---

## 实验设置

| 项目 | 取值 |
|------|------|
| 模型 | `OPENAI_MODEL` 环境变量配置（默认 `gpt-4o-mini`，本仓库实际接 MiniMax 兼容协议） |
| `top_p` | 1（仅变动 temperature，避免双重采样） |
| `max_tokens` | 2048 |
| 系统提示词 | `src/agent/prompts.ts` 的 `SYSTEM_PROMPT`（旅游助手场景） |
| 工具 | 关闭 tool_choice 仅做纯文本对比，避免工具调用结果干扰文本风格观察 |
| 重复次数 | 每个 temperature 各跑 3 次，观察组间差异 |

---

## 测试 query

固定使用以下 3 条 query，覆盖三种典型场景：

| ID | 类型 | Query |
|----|------|-------|
| Q1 | 开放推荐 | 帮我推荐一个适合冬天去的国内目的地，要有雪景。 |
| Q2 | 结构化生成 | 给我一份云南三日游的行程，按"上午 / 下午 / 晚上"分时段列出。 |
| Q3 | 事实型问答 | 哈尔滨冰雪大世界一般什么时候开园？ |

---

## 观察结论（实测后请回填具体输出）

> 下表为预期模式，跑完后请用真实输出替换示例文本，并在「样本」列贴入实际段落。

| Query | T=0.0 | T=0.4 | T=0.9 |
|-------|-------|-------|-------|
| Q1 推荐 | 倾向给出最高频"标准答案"（如哈尔滨/长白山），三次回答几乎一致 | 在主流答案基础上偶尔出现亚布力、雪乡等次主流目的地 | 出现明显差异化推荐（如阿尔山、可可托海），偶尔出现非雪景地 |
| Q2 行程 | 时段划分稳定、措辞接近模板 | 行程结构稳定，但景点替换更灵活 | 偶尔出现结构走偏（如把"晚上"合并到"下午"） |
| Q3 事实 | 回答简短直接，复述常见时间段 | 与 0.0 相近，措辞略有变化 | 出现编造细节风险（年份、活动名称差异） |

### 通用规律

1. **温度越低 ≠ 越准确**：Q3 事实型问答下，0.0 与 0.4 几乎无差，但 0.9 明显增加幻觉风险。
2. **温度越低 ≠ 越好读**：Q1/Q2 推荐场景下，0.0 输出常显得"模板化"，缺少风格变化。
3. **结构稳定性随温度下降而提升**：Q2 这类需要严格分段的输出，0.0 / 0.4 的结构稳定性显著优于 0.9。

---

## 选型建议

结合本项目"旅游助手"场景：

- **默认值 `LLM_TEMPERATURE=0.4`**：在多样性与稳定性之间取折中，既避免模板化、又保留结构。
- **未来路由分场景调整**（对应阶段5 Task 5.2）：
  - 工具调用 / 结构化抽取（如解析用户偏好为 JSON）→ 强制 `0.0~0.2`
  - 自由生成（攻略文案、风格化推荐）→ `0.5~0.7`
  - 事实复述 / RAG 答案合成 → `0.0~0.3`，配合 §3.5 溯源约束降低幻觉
